# KubeVirt S3 Post-Processor

Type: `kubevirt-s3`

<!--
  Include a short description about the post-processor. This is a good place
  to call out what the post-processor does, and any additional text that might
  be helpful to a user. See https://www.packer.io/docs/provisioners/null
-->

The S3 post-processor is used to export the disk image produced by the `kubevirt` builder to an S3 bucket.
A Kubernetes job downloads the disk image from the Virtual Machine Export and uploads it to the bucket as `<vm_name>.img.gz`.


<!-- Post-Processor Configuration Fields -->

**Required**

- `s3_bucket` (string) -  S3 bucket where exported VM images are stored

- `s3_region` (string) -  S3 region used to initialize the AWS CLI uploading the exported VM image

- Credentials, one of:
  - `s3_access_key_id` (string) and `s3_secret_access_key` (string) - Static credentials with S3 permissions.
  Sensitive fields
  - `service_account_name` (string) - Service Account Name with associated S3 permissions to export a disk image to S3 (recommended, takes priority)

<!--
  Optional Configuration Fields

  Configuration options that are not required or have reasonable defaults
  should be listed under the optionals section. Defaults values should be
  noted in the description of the field
-->

**Optional**

- `image_format` (string) -  Format the disk image is converted to with `qemu-img` before the upload, stored as `<vm_name>.<image_format>`.
The job needs scratch space on its node for the data of the disk, twice. The empty blocks of the disk take no space
Accepted values: `qcow2`, `vmdk`, `vhdx`, `vdi` - Defaults to empty string (compressed raw image, no conversion)

- `keep_export` (bool) -  Keep the Virtual Machine Export once done, for another post-processor to use it.
The last post-processor of a build should delete it: with the export go the stopped Virtual Machine and its disk. Otherwise they stay until the export expires, after 2 hours by default
Defaults to `false`

- `s3_endpoint_url` (string) -  URL of an S3-compatible storage to upload to instead of AWS S3, such as Garage, MinIO or Ceph
Must be an `http` or `https` URL, `s3_region` is then the region configured on that storage
Defaults to empty string (AWS S3)

- `s3_key_prefix` (string) -  Key prefix for all the exported VM images
Defaults to empty string (image stored at the root of the bucket)

- `s3_object_name` (string) -  Name of the image in the bucket, without its extension. Letters, digits, `.`, `_`, `+` and `-` are accepted
Defaults to `vm_name` of the builder

- `upload_timeout` (duration string) -  Timeout duration for the download, the conversion and the upload
A failed job is retried once, within this timeout
Defaults to `10m`

### Example Usage


```hcl
 source "kubevirt" "linux" {
  ...
 }

build {
  sources = ["source.kubevirt.linux"]

  post-processor "kubevirt-s3" {
    image_format         = "qcow2"                       # Optional
    s3_access_key_id     = "S3_ACCESS_KEY_ID"
    s3_bucket            = "virtual-machine-disk-images"
    s3_key_prefix        = "kubevirt"
    s3_region            = "us-east-1"
    s3_secret_access_key = "S3_SECRET_ACCESS_KEY"
    upload_timeout       = "10m"                         # Optional
  }
}
```
